# Xcsc 1.0.3

- 修复 Windows 轮转日志查询在扫描期间发生归档移动时可能遗漏记录、却推进游标的问题。新增 `query_windows_rotating_logs`，在捕获日志字节期间持有共享读锁；写入端只在初始化和轮转目录变更期间持有独占锁。
- 日志查询遇到锁竞争时返回可重试的 `log_snapshot_busy`；follow 查询保留游标并在后续轮询重试，截止时仍繁忙则明确返回错误。
- 写入端等待读锁至多五秒，超时返回 `LogError::ReaderBusy`，不接受本次记录、不移动归档，也不永久禁用日志写入；释放读锁后可重试。
- 补充原生 Windows 轮转并发、保留边界、重复记录、锁竞争与超时恢复、进程退出释放锁、旧版本边界及权限回归测试。

Windows 日志目录新增私有 `.STEM.jsonl.read.lock` 文件。新读取端拒绝缺少该文件的旧目录，不创建或修复标记；需由新写入端成功初始化后才能读取。旧写入端不能重新打开含新标记的目录，升级必须同步更新并重启写入端与 CLI，不能把旧写入端直接回滚到此目录。此变更不改写日志载荷，不更改既有权限策略。

消费者应固定 xcsc `=1.0.3` 与本次发行对应的完整 Git revision，更新 `Cargo.lock`，并将 Windows 轮转日志调用接入 `query_windows_rotating_logs` 后重新执行消费检查和产品测试。仅升级依赖而未更新调用方，不构成端到端修复。配置、业务协议、ABI 和持久状态版本不变；此库不单独部署，旧标签及归档保持不可变。
